# ainfra v0.1.0

## Added

- A standalone Rust CLI for project initialization, validation, planning,
  reviewed apply and destroy operations, status, outputs, and inventory.
- Embedded schemas and the Hetzner Kubernetes-ready baseline template.
- Verified Linux release archives and a checksum-validating installer.

## Changed

- The product boundary moved from a repository-coupled Python wrapper to an
  installed binary that operates from a user-owned infrastructure project.
- Release publication now uses explicit development, prerelease, release, and
  stable branch lanes.

## Fixed

- Legacy Python plan records can be inspected without mutating infrastructure.
- Host release packaging supports the standard macOS `tar`; Homebrew GNU tar
  is not required.

## Known limitations

- The initial built-in infrastructure template targets Hetzner Cloud.
- Native macOS archives are published by the explicit host-completion phase.
- Live provider validation requires an operator-approved, cost-bounded test
  environment and credentials.

## Install

```sh
curl --proto '=https' --tlsv1.2 --fail --location \
  --proto-redir '=https' \
  https://github.com/projectious-work/ainfra/releases/download/v0.1.0/install.sh \
  -o /tmp/ainfra-install.sh
AINFRA_VERSION=0.1.0 sh /tmp/ainfra-install.sh
ainfra --version
```

## Rollback

Remove the installed binary or reinstall a previously verified release by
setting `AINFRA_VERSION`. Infrastructure rollback is deliberately separate:
review the last recorded plan and use an exact reviewed destroy plan when
resources must be removed. Never delete local state as a rollback mechanism.
